## dsh-plugin-radar 是做什么的？

dsh-plugin-radar 是一个汇集插件目录、兼容性记录和公开数据的 DSH 插件生态雷达。它帮助使用者寻找候选，也方便市场维护者把同一份生态数据接入自己的工具；项目并非已提供 npm 安装方式的运行时扩展。

这个 DeepSeek Harness 插件发现项目将生产快照、历史基线与社区登记归并后生成目录。兼容性状态适合辅助筛选，不能替代当前环境中的验证。项目由社区维护，与 DeepSeek 官方无隶属关系，记录和推荐也不代表官方背书。

## dsh-plugin-radar 核心功能

- **插件发现与筛选**：站点提供浏览、筛选、精选和整合包入口，仓库同时提供完整及分类 Markdown 目录。精选与整合包成员由人工策展。
- **兼容性记录**：区分可用、不兼容、待定和未测四档，汇总多轮历史判定。运行级结论不等于完整功能、性能或安全审计。
- **公开 JSON**：状态接口提供快照指针与统计，明细接口包含仓库、判定、星标和描述，无需密钥即可读取。
- **社区登记与更正**：支持通过仓库 topic 或 PR 补充条目；判定有争议时，可提交版本信息与可复现日志。
- **公开聚合引擎**：发现、聚合、渲染和分发组件可供查看，但生产运行级测试引擎尚未开源。

## 怎么安装和使用 dsh-plugin-radar？

README 没有提供 DSH 安装命令，现有信息也无法确认 npm 包名，因此这里不生成安装指令。普通使用者从站点开始，数据使用方在自己的应用中配置读取与缓存。

1. 打开 `https://adamplatin123.github.io/dsh-plugin-radar/` 浏览候选。偏好仓库阅读时，可查看 `PLUGINS-ALL.md`、`catalog/all` 和 `docs/catalog-highlights.md`。
2. 选择条目后，先阅读原插件仓库的安装、权限与卸载说明。在测试环境验证最小功能，并保留回滚路径，不要仅凭历史“可用”状态直接部署。
3. 接入前阅读 `docs/api.md`。状态地址为 `https://raw.githubusercontent.com/AdamPlatin123/dsh-plugin-radar/main/data/latest.json`，明细地址为 `https://raw.githubusercontent.com/AdamPlatin123/dsh-plugin-radar/main/data/plugins-all.json`。
4. 后台统一刷新，可从每 15 分钟一次开始并随机错峰；服务器提供 `ETag` 时使用条件请求。较大规模接入应通过自己的缓存或镜像分发。
5. 新数据校验通过后再替换缓存，界面显示数据日期与刷新状态。先读小型状态文件，但不能仅凭快照编号推断明细未变化。

需要跨文件一致性时，应固定同一完整 Git 提交读取统计与明细，并逐档核对总数。引用数据时，项目建议注明雷达名称和对应快照编号。

## dsh-plugin-radar 报错怎么排查？

请求超时、限流或服务端临时故障时，应设置超时并退避重试，建议最多尝试三次；收到 `Retry-After` 则按提示安排下次请求。刷新失败后继续提供上次成功的数据，不要用未校验内容覆盖缓存。

不同来源的数据不一致时，先核对日期，镜像同步可能延迟。公开 JSON 暂时不可用通常不影响已经部署的目录浏览，因为站点数据在构建时打包。

若判定与实际运行不符，可通过 Issue 提供仓库地址、插件版本、DSH 版本与复现日志。扁平清单尚未完整公开逐条 commit、被测版本、时间和日志；全局版本指针不能补足这些证据，也不能证明最新版兼容。
