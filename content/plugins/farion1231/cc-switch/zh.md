## cc-switch 是做什么的？

cc-switch 是一个面向 DSH 用户的桌面配置工具；如果你在找可直接装进宿主的 DeepSeek Harness 插件，当前 README 片段没有提供这种安装方式。它的主要用途是切换 API 服务商，也能在同一界面管理 MCP、技能和提示词，减少手改 JSON、TOML 或 YAML 配置文件的次数。

如果你平时在 DeepSeek Harness、Claude Code 或 Codex 之间来回使用，可以先在桌面应用里确认要管理哪个客户端，再处理对应的配置。比如，只想换掉当前请求使用的服务商，就先调整服务商条目，不必同时改动 MCP 或提示词。这样在验证时，也更容易判断是哪一项变更影响了结果。

## cc-switch 核心功能

- **API 服务商切换**：在桌面界面配置并选用目标服务商。已准备好多个服务商条目时，可以直接切换，不用为了改回原来的设置而重新手填配置。
- **MCP 配置管理**：在应用内集中查看和维护 MCP 条目。编辑前先确认目标客户端，避免把本来要给 DSH 使用的配置改到了另一个工具上。
- **技能与提示词管理**：在同一个应用里维护这两类内容。调整工具用法或日常提示词时，可以单独检查对应条目，不必把它们和服务商配置混在一起改。
- **多平台桌面使用**：项目提供 Windows、macOS 和 Linux 版本。配置主要在桌面界面进行，适合希望减少直接编辑配置文件的用户。

## 怎么安装和使用 cc-switch？

当前 README 片段未列出 DSH 安装命令。请从 `farion1231/cc-switch` 的项目发布页下载与你的操作系统匹配的桌面版，再按安装包提示完成安装；不要把同名 npm 包当成已经验证可用的宿主插件。

1. 打开桌面应用，先确认当前要管理的客户端是 DeepSeek Harness。如果你也用 Claude Code 或 Codex，切换配置前尤其要留意这一点。
2. 如果目的是更换模型接入服务，在服务商相关界面选择已有条目，或按所用服务商提供的信息完成配置，再切换到目标条目。
3. 如果要维护 MCP、技能或提示词，在桌面端进入对应的管理界面。首次使用时建议一次只改一类配置，确认效果后再继续。
4. 回到 DSH 进行验证。服务商切换后可先发一条简单请求；如果改的是 MCP 或技能，则用一个只涉及该条目的任务检查结果。

## cc-switch 报错怎么排查？

当前 README 片段未给出针对 DSH 的具体报错和修复方法。遇到配置不生效或请求失败时，可以按下面的顺序检查，避免没找出原因就反复重装。

1. **确认客户端和 profile**：核对桌面端改的是哪个客户端，再确认当前 DSH 会话使用的 profile，避免在另一套环境里验证。
2. **检查相关插件是否启用**：如果出问题的功能依赖另一个 DSH 插件，先确认该插件已在实际使用的 profile 下启用。这一步不意味着要把桌面应用装成插件。
3. **重启 DSH 后复测**：尽量重复同一个简单操作，比较重启前后的表现。单独验证刚修改的项目，不要为了排查一次性切换多个设置。
4. **查看版本和日志**：记下桌面端与 DSH 的版本，以及问题出现前最后一次配置变更，再查看相关日志。分享日志前注意隐藏密钥等敏感信息。
