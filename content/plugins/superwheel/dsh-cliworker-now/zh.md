## dsh-cliworker-now 是做什么的？

dsh-cliworker-now 是一个把多种 CLI 智能体组织到侧栏独立对话中的 DSH 插件。它面向需要分派代码审查、写作审校或持续跟进任务的用户：主对话负责派遣与接收结果，侧栏展示每个智能体的过程、用量和状态，结束后还能按名字继续追问。

这个 DeepSeek Harness 插件安装后显示为 CLI Worker / CLI Worker Now。它接入 Codex、Claude Code、Pi、OpenCode 等工具，保留各自账号、模型和原生会话，不附带模型服务、订阅或 API 额度。

## dsh-cliworker-now 核心功能

- **独立对话与续聊**：Worker 使用宿主原生对话视图、输入框、模型控件和用量统计，支持排队、停止与结束后继续交流。
- **命名与角色预设**：为智能体设置唯一名称、角色和自定义提示词。首次派遣必须明确选型，后续可关闭询问，使用保存的默认设定。
- **原生账号与工具**：模型和思考强度按实际 CLI 与当前账号读取。优先使用原生工具，符合条件的缺失能力经 `dsh_worker_tools` 提供，并接受宿主审批；各 CLI 的工具桥支持范围不同。
- **权限与调度控制**：按原生能力提供询问、自动审批和完全权限模式，规划模式拒绝写入。同一会话互斥，CLI 失败时不会自动换用另一种。
- **项目副本并行写入**：同目录写任务默认串行。开启并行后，新增任务在私有副本执行，由主 Agent 整合回项目，保留为未提交改动。

## 怎么安装和使用 dsh-cliworker-now？

提供的 README 片段未包含 DSH 安装命令，npm 包名也未确认，因此这里不生成安装指令。请查阅仓库完整安装说明；设置中的「更新 CLI」页用于管理外部 CLI 的安装与更新。

1. 准备环境：支持 macOS、Windows，要求 Node.js ≥ 22.19.0，当前宿主适配目标为 0.2.2-rc.3。
2. 安装所需 CLI 的原生版本，完成各自登录或 API 配置。在「CLI Worker 设置」的「更新 CLI」页检查版本、安装方式与更新说明。
3. 首次派遣前选择 CLI、模型和角色，给 Worker 命名并选择权限。尚未选择权限的 Worker 跟随主对话预设，选过后按所选档位运行。
4. 在主对话点名 CLI 并说明任务，到侧栏查看执行记录、回应授权请求或补充指令。主 Agent 派遣的任务在主对话审批，子会话发起的轮次在该子会话审批。
5. 按同一个名字继续任务。换号后使用当前账号；若原生会话无法恢复，历史记录会随新会话发送给当前账号的服务商。

## dsh-cliworker-now 报错怎么排查？

侧栏入口未出现时，先确认当前 profile、插件是否启用，再重启宿主并查看版本和日志。CLI 无法调用时，检查原生安装路径及账号配置；模型能列出不等于拥有调用权限。

结合时间线判断任务状态。工具步骤失败后被 CLI 自行处理，整轮仍可完成；最后一个工具失败后直接结束，会标为「结果待核实」。拒绝授权的记录保留在时间线，CLI 随后自行结束时可能显示「已完成」。

安装或更新失败时，查看「更新 CLI」页的命令、输出和下载进度；部分方式只提供手动说明。WorkBuddy 属于试验性接入，国际版尚未完成所述真实任务验收，不能将所有列出的 CLI 视为具有相同验证范围。
