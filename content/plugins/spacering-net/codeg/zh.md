## codeg 是做什么的？

codeg 是一个聚合多个编程智能体、历史会话和代码改动的独立工作区，并非已确认可安装的 DSH 插件。如果你是 DeepSeek Harness 用户，想把 Claude Code、Codex 和 OpenCode 的工作放在同一个界面里，可以把它作为单独运行的工具，而不是装进 DSH。

它适合需要在多个智能体之间切换、又想保留任务上下文的开发者。例如，你可以先找到上次留下的实现讨论，把相关会话交给另一个智能体接着分析，再对照项目文件和 Git 差异判断它改了什么。

## codeg 核心功能

- **统一对话界面**：在同一个工作区调用受支持的编程智能体。对话会以结构化方式展示工具卡片、实时差异和可交互的回复，不用来回切换终端查看输出。
- **历史会话聚合**：导入智能体保存在磁盘上的会话，用搜索找回旧对话，或加标签整理。找回记录后，可以继续原来的讨论，也可以把它作为其他任务的上下文。
- **多智能体协作**：在对话中用 `@` 指定接手任务的智能体。多个智能体并行工作时，可以在对话中查看各自的进度。
- **独立工作树待办**：把任务排入待办，让智能体在隔离的 Git 工作树里处理。完成后先审阅差异，再决定是否批准改动。
- **无限画布**：把对话、文件、终端和笔记摆在同一块画布上。审阅改动时，可以让相关讨论和项目文件并排显示。

## 怎么安装和使用 codeg？

当前 README 片段没有提供 DSH 安装命令，仓库信息也未确认 npm 包名。请按独立应用安装，不要把仓库名直接填进 `dsh plugin` 命令。

1. 选择运行方式。想在本机使用时，到 `spacering-net/codeg` 仓库的 Releases 页面，下载适用于 macOS、Windows 或 Linux 的桌面版。需要自托管时，查看官方部署文档，按其中的服务器或 Docker 方式操作。
2. 打开应用后，进入要处理的项目工作区，从支持列表里选择一个智能体。需要接入其他工具时，查阅官方文档的自定义智能体章节，按 ACP 接入说明配置；这一步在应用侧完成，不是在 DSH 的 profile 里添加插件。
3. 先发一条简短消息确认所选智能体能回复。要接着处理已有任务，再使用会话聚合功能导入并搜索磁盘上的历史记录；新任务则可以直接从当前工作区开始。
4. 需要换人处理时，在对话里用 `@` 分派任务或引用已有会话。涉及文件修改时，先结合项目文件查看实时差异，再决定是否接受结果。

## codeg 报错怎么排查？

当前 README 片段未列出具体错误码。先区分问题出在应用启动、智能体连接，还是历史会话导入，再检查对应环节。

- 应用打不开或连不上自托管服务时，核对系统与安装版本是否匹配，确认使用的是预期的部署实例，再查看应用或服务日志。
- 智能体不回复时，确认当前选择的是预期的智能体；如果是自定义接入，按官方文档复查 ACP 配置，重启应用后用简短消息再试。
- 搜不到历史对话时，先确认当前工作区和会话来源，再检查原智能体是否已将会话保存在磁盘上。记录应用版本和日志，有助于区分导入失败与搜索无结果。
