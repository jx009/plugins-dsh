## crossdesk 是做什么的？

crossdesk 是一个通过本机 MCP 服务让智能体观察和操作远程电脑的 DSH 插件。它面向需要把远程桌面接入开发流程的用户，提供实时监看和人工接管，让人能够跟随操作过程并按需接手。

作为 DeepSeek Harness 插件，它的接入说明位于仓库 `apps/mcp/README.md`。所给片段将 MCP 标为开发版，功能段落提到从源码构建，平台表又说明可安装单个插件包；具体分发方式与配置应查阅该文档。项目本身基于 MiniRTC，另有桌面、浏览器、移动端和终端客户端，支持自托管。

## crossdesk 核心功能

- **Agent / MCP：** 通过本机服务授权智能体访问远程电脑，提供多会话、实时监看和人工接管能力，适合需要人工跟进的远程操作流程。
- **剪贴板与文件工具：** MCP 能力列表包含这两类工具。桌面客户端另有双栏目录浏览、文件和文件夹双向传输、拖放及任务管理，不能据此认定所有界面功能都已暴露给智能体。
- **DeskHub 桌面墙：** 集中预览多台设备，支持分组、放大操控、群控和批量文件分发。群控会向全部已连接设备发送输入，关闭桌面墙会断开其中的连接。
- **局域网 IP 直连：** 支持相应模式的桌面端可用地址、端口和密码连接，无需云端信令；支持 IPv4、IPv6 和可达的 VPN 接口。
- **浏览器与终端访问：** Web 控制端需要支持 WebRTC 的浏览器。CLI 提供 ANSI、Kitty、Sixel 画面，默认只读且静音，可明确开启键鼠操作。

## 怎么安装和使用 crossdesk？

当前 README 片段没有 DSH 安装命令，因此此处不生成命令。文中出现的 `@chunkdash/crossdesk-cli` 是终端客户端包，不能当作已确认的插件包；请先查看 `apps/mcp/README.md` 中的安装、构建和配置说明。

1. 准备被控电脑。下载匹配系统和 CPU 架构的桌面安装包；Windows、macOS、Linux 支持被控，浏览器和移动端用于控制。
2. 启动桌面客户端，切换到 ID 模式，等待服务器连接成功，然后查看“本桌面”中的九位设备 ID 和当前密码。
3. 先用另一台电脑、移动端或浏览器输入 ID 和密码验证连接。使用自建服务器时，两端必须接入同一服务。
4. 按 MCP 专用文档配置本机服务及插件。当前片段未提供 DSH 配置路径、工具名称或调用语法，不能直接从桌面操作步骤推导。
5. 接入后按文档使用远程观察与操作能力，并通过监看和人工接管跟进会话。不同客户端的功能范围应分别核对。

## crossdesk 报错怎么排查？

macOS 没有画面或无法输入时，检查屏幕录制与辅助功能权限，分别对应采集和键鼠操作。CLI 还要求被控电脑提供可捕获的图形会话，信令服务支持 `cli` 临时身份注册。

桌面端缺少 IP 模式按钮时，在“设置 → 常规 → 网络连接”启用直连并保存。检查两端网络互通及实际端口；默认值为 `52888`，关闭直连设置会停止监听并断开相关会话。

开启可信设备限制后，仅有密码不能通过验证，控制端还需支持认证协议并加入信任名单。当前 CLI 和移动客户端尚未实现该认证；自托管环境使用新版设备密钥登录前，应按说明升级服务端。

插件未在 DSH 中出现时，可检查目标 profile、启用状态、版本与日志，再重启应用。这是通用加载检查，所给片段没有提供插件专属错误码或修复命令。
