## powercontext 是做什么的？

powercontext 是一个面向长期记忆与任务交接的 DSH 插件资源，其核心是独立的智能体上下文服务。它把决策、约束、证据和进度保存在会话之外，帮助开发者在换会话、换智能体或交给同事时延续工作。对于寻找 DeepSeek Harness 插件的用户，需要区分服务能力与安装支持：当前 README 片段没有给出可直接安装的 DSH 包。

项目可作为标准 Server 运行，也允许应用嵌入 Core 协议。README 明确提到 Codex 与 Claude Code 之间的上下文延续。所有数据归属某个 Scope，其中包含来源记录、记忆生命周期、审核收件箱和交接历史；Scope ID 用于选择数据，不代表用户身份或执行授权。

## powercontext 核心功能

- **长期记忆与版本追踪**：Memory 保存事实、决策、约束和下一步行动。条目可处于活跃、遗忘、合并或退役状态，遗忘后仍保留内容与历史，便于恢复。
- **结构化任务交接**：Handoff 串联工作约定、待提交交接、接收确认和任务结果。`handoff_current_work` 先产生临时交接内容，提交后才形成持久版本。
- **经验与技能审核**：Experience 记录情境、行动、结果与经验，审核通过后才参与召回。Skill 保存操作步骤和验证检查，获批后仍需显式导出才能被宿主发现。
- **有限预算召回**：`PreparedContext` 按配置选择活跃记忆、获批经验等内容，并应用统一字节预算，返回 `ready` 或 `empty`。召回记录属于历史信息，不构成新的指令权限。
- **多种服务接口**：HTTP 提供完整远程应用接口，Python Client 提供类型化访问，MCP 提供面向智能体的精选能力；Dashboard 和桌面预览支持检查已保存的上下文。

## 怎么安装和使用 powercontext？

当前材料没有 DSH 安装命令，也没有确认 npm 包名，因此无法可靠提供插件安装命令。应先按项目 Quickstart、Manual startup 和 Integrations 文档完成部署与接入；片段未提供 DSH 专用配置文件位置或连接参数。

1. 选择运行标准 Server，或在应用中嵌入 Core 协议。使用外部 OceanBase 的 Kubernetes 部署，可参考项目提供的 Helm 指南。
2. 根据应用或智能体的接入需求选择 HTTP、MCP 或 Python Client，再按对应文档配置连接。
3. 连接服务后选择准确的 Scope。通过工作区视图搜索记忆、查看指定版本，或为下次会话保存笔记。
4. 将需要长期保留的约束和事实直接写入 Memory。直接写入不依赖模型；从 Source 自动提取内容需要配置生成管线。
5. 在阶段边界准备 Handoff，需要保留里程碑时再提交。接收方读取交接并记录确认，结束后将状态和检查结果保存为 Task Outcome。
6. 审核经验与技能候选项。若要让宿主发现技能，还需导出已批准的精确版本，批准本身不会触发安装或执行。

## powercontext 报错怎么排查？

README 片段没有列出 DSH 专用错误码。若接入后未显示，先确认当前 profile、集成是否启用，再重启 DSH，并查看版本与日志。

查不到记忆时，先核对 Scope，再检查条目的生命周期状态和经验审核状态。活跃记忆与当前获批经验才会进入相应召回路径，待审核或被拒绝的经验不会参与；`PreparedContext` 返回 `empty` 也可能是正常结果。

来源提取不可用时，检查是否已配置生成管线。技能获批却无法发现时，检查是否导出了对应的精确版本。以上属于文档支持的前提检查，具体配置仍需查阅完整操作文档。
