## desktop-cc-gui 是做什么的？

desktop-cc-gui 是一个为 DSH 等命令行编程引擎提供图形界面的桌面客户端。开发者可以选择项目，通过对话处理代码任务，并查看输出和工具调用。对于搜索 DeepSeek Harness 插件的用户，它提供的是桌面集成能力；现有资料并未将其定义为可通过插件命令安装的软件包。

它还接入 Claude Code、Codex CLI、OpenCode 等引擎。Rust 后端通过各自的协议适配器处理流式事件、会话历史和供应商渠道，界面展示不依赖终端画面抓取。项目使用 Tauri 2、React 18、TypeScript 和 Rust，支持 macOS、Windows、Linux。设置和状态保存在本地，发往模型供应商的内容遵循对应 CLI 配置的渠道边界。

## desktop-cc-gui 核心功能

- **流式输出与工具调用**：实时查看响应、思考轨迹和工具活动。引擎上报用量后才会显示 token 数据，DSH 兼容矩阵也列出了上下文窗口支持。
- **会话历史与恢复**：支持恢复历史对话、重命名会话、停止响应和消息队列。既能接着处理已有任务，也能中断当前生成。
- **模型选择与上下文**：DSH 支持模型选择器、图片附件和 `@` 文件引用，可在交互中选择模型并补充项目材料。
- **子智能体展示**：支持通过调度面板展示子智能体活动。团队模式的多智能体编排仍标记为不支持，不能把两者视为同一功能。
- **会话命令与技能入口**：支持 `/new` 和 `/clear`。`/compact`、斜杠命令与技能选择器、供应商与渠道切换均为部分支持。

## 怎么安装和使用 desktop-cc-gui？

所提供的 README 片段没有安装命令，仓库信息也未确认 npm 包名，因此无法给出经过核实的 `dsh plugin` 安装指令。请先查阅项目完整安装文档；把它当作普通 DSH 插件套用安装模板，没有资料依据。

在桌面应用和所选运行时可用之后，可按以下顺序开始使用：

1. 打开 ccgui，选择要处理的项目，并使用 DSH 引擎开展任务。
2. 确认对应 CLI 使用的供应商渠道。README 说明了渠道决定数据发送边界，但片段没有给出配置文件位置或具体设置菜单。
3. 使用模型选择器选择模型，根据需要通过 `@` 引用文件或添加图片附件。
4. 输入代码修改、问题分析等请求，观察流式响应与工具调用。需要中断时使用停止功能。
5. 后续从会话历史恢复工作；开始独立对话时使用 `/new`，清空当前上下文时使用 `/clear`。

不同引擎的能力并不完全一致。切换引擎后，应以兼容矩阵对应列为准，不能把其他引擎支持的权限模式或导入功能直接套用到 DSH。

## desktop-cc-gui 报错怎么排查？

先判断缺少的功能是否在支持范围内。DSH 只列出 auto 权限模式，不支持推理强度调节、Todo 列表渲染、团队模式、快速模式、CC Switch 导入和原生 `/mcp` 命令。对应入口不可用时，应先核对这些限制。

技能选择、渠道切换或上下文压缩表现不完整时，注意它们均标记为部分支持。README 片段没有提供具体错误码或修复命令，不能据此承诺完整兼容。

对于一般运行异常，可确认选中的引擎与预期 profile 名是否一致，重启桌面应用和 DSH，再检查版本及可用日志。进一步定位时，记录失败操作、发生阶段和相关日志，区分会话恢复、渠道配置或响应生成环节的问题。
