## dsh-purge 是做什么的？

 dsh-purge 是一个用于评估本地宿主策略的 DSH 插件。它关注的是官方客户端如何处理提示词、审批和沙箱限制，而不只是模型如何回答。排查时，这两层要分开看：请求可能先被宿主限制，不能仅凭最后的表现就判断是模型拒答。

当前收录的是镜像仓库。所给 README 标注的版本为 `1.1.71`，并注明维护已暂停，不保证兼容后续发布的宿主版本。这个项目会涉及本机官方软件包和配置，不只是增加一个界面按钮。本文只介绍兼容性检查、状态核对与恢复，不提供绕过审批或沙箱限制、注入提示词或运行攻击演练的步骤。

## dsh-purge 核心功能

- **补丁状态查看**：侧栏按组显示改动状态。在接手他人配置过的设备时，可以先看这里，不必把插件列表中的存在与否当成补丁是否生效的依据。
- **官方客户端分档**：官方 Web 和桌面端使用不同的配置档。即使运行在同一台电脑上，也要分别核对，不能用其中一端的状态推断另一端。
- **恢复和卸载**：`Clean` 页把 `Restore` 和 `Uninstall` 分开列出。需要撤销宿主改动时，应先检查恢复结果，再处理插件本身是否保留。

## 怎么安装和使用 dsh-purge？

本页不提供安装命令。如果你在评估现有环境，可以按下面的顺序核对配置；如果尚未安装，也可以先用这些信息判断当前环境是否在文档列出的范围内。

1. 确认当前运行的是官方 Web 还是官方桌面端。前者使用 `web`，后者使用 `desktop`；README 不再维护对社区桌面版的支持。
2. 在对应的配置档里核对插件记录，再比对宿主和 Node.js 版本。文档中的发行版面向 DSH `0.2`，列明的官方桌面版为 `0.2.0-rc.2`，运行时要求 Node.js `18` 或以上。
3. 如果已经安装，在会话标题旁打开插件侧栏，到 `Clean` 查看补丁状态。仅添加插件不会修改宿主；如需撤销已写入的改动，使用 `Restore`，确认恢复结果后再决定是否选择 `Uninstall`。

## dsh-purge 报错怎么排查？

- 看不到侧栏入口时，先检查当前客户端使用的配置档，再确认插件是否已启用。若两项都正确，可以重启当前客户端复查，并查看启动日志。
- 更新 DSH 后才出现异常，先记录宿主、插件和 Node.js 的版本，再和文档中的支持范围对照。不要把维护暂停前列出的兼容信息视作对新版的支持承诺。
- 如果在 Windows 上遇到启动窗口闪现，检查是否满足文档针对无闪窗运行列出的 Node.js `22` 或以上要求。这与插件能否在基础环境中运行是两个问题。
- 如果恢复后仍然看到异常，分别记录补丁页面显示的状态和启动日志中的实际报错。这样可以区分是恢复结果尚未确认，还是客户端仍存在独立的启动问题。
