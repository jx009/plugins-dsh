## dsh-purge-safe 是做什么的？

 dsh-purge-safe 是一个面向本地主机策略评估的 DSH 插件。它关注的是官方 DeepSeek Harness 在模型之外做了哪些处理，例如如何改写提示词、处理工具审批和执行沙箱策略。一次请求没有完成，不一定是模型拒绝，也可能是宿主在模型作答前拦截了某个操作。项目把这两层行为分开，便于检查问题出在哪一层。

这个 DeepSeek Harness 插件依赖已经安装的官方宿主，不是独立客户端。仓库将 2.0.0 的适配目标标为 DSH 0.2.2-rc.3，列出的运行环境为 Node.js 18 或更高版本。它处理的是本机官方软件包和本地配置，不修改 Harness 源码树。

## dsh-purge-safe 核心功能

- **会话侧栏**：入口位于会话标题旁，点击后打开右侧面板。面板分为 `Clean` 和 `Drill` 两页；只想核对本地状态时，看前者即可。
- **分组补丁状态**：`Clean` 将状态按组展示，方便确认当前宿主里的本地改动。本地构建默认不在启动时自动应用改动，因此插件已加载和补丁已应用是两回事。
- **恢复与卸载**：两项操作在 `Clean` 中分别列出。想撤回已有改动时，先认准 `Restore`，操作后再回看分组状态。
- **双宿主支持**：仓库列出了官方 Web 版和桌面 EXE 版，并注明此版本支持 `Super Agent`（超级智能体）。两个宿主需要分别管理，不能用一个宿主的状态判断另一个。

## 怎么安装和使用 dsh-purge-safe？

所提供的 README 片段未展示完整安装命令，本页不列出安装命令。安装前先核对官方宿主和 Node.js 版本；如果插件已经存在，按下面的顺序定位配置、查看状态或恢复改动。

1. 确认你正在使用哪种宿主：通过 `dsh web` 启动的是 Web 版，官方桌面 EXE 是另一个入口。后续核对配置和状态时，始终使用同一个宿主。
2. 核对本地配置目录。仓库注明，插件依次查找 `DSH_HOME`、`dsh` 启动程序旁的 `.dsh`，以及用户主目录下的 `~/.dsh`。如果配置了 `DSH_HOME`，不要直接把主目录下的文件当成当前配置。
3. 进入会话，从标题旁打开侧栏，在 `Clean` 查看分组状态。如果已有本地改动需要撤回，在对应宿主选择 `Restore`，然后重新核对状态。两种宿主都使用过时，分别查看。

## dsh-purge-safe 报错怎么排查？

- **找不到入口**：先确认打开的是安装时使用的宿主和配置档案，再检查插件是否启用。重启 DSH 后回到会话页面，查看标题旁是否出现按钮。
- **状态与预期不符**：先区分插件是否加载和本地改动是否生效，再核对当前配置目录。切换 Web 版和桌面版后，应读取当前宿主的状态，而不是沿用上一次的结果。
- **恢复失败或重启后仍有异常**：核对插件版本、DSH 版本和 Node.js 版本，并查看对应宿主的日志。记录异常发生在启动、打开侧栏还是恢复时，以便区分加载问题和恢复问题。
