## agentrq 是做什么的？

agentrq 是一个面向人机任务协作的 DSH 插件目录项目，其主体 AgentRQ 是自托管协作平台。它帮助开发者把目标拆成任务、交给智能体执行，并在同一工作区跟踪进度、回答问题和处理权限请求。仓库标签包含相关生态标识，但当前 README 片段未说明专用接入步骤。

智能体通过 MCP 读取工作区状态、领取分配的任务并更新进度，操作结果实时同步到看板。仓库描述也提到支持 ACP 的 harness。对于寻找 DeepSeek Harness 插件的用户，需要先核实完整集成文档中的连接方式，再配置自己的运行环境。

## agentrq 核心功能

- **可视化任务看板**：提供列表和 Kanban 两种视图，可从不同设备查看当前工作、待处理请求与已完成任务，方便集中跟进多个智能体的进度。
- **定时与周期任务**：任务可指定启动日期，也可设置每 15 分钟、每小时、每天、每周或自定义日期执行。后台轮询器每分钟检查一次，为到期任务创建运行。
- **事件驱动工作流**：任务完成后可发出 `qa_passed` 等命名事件，订阅它的工作区会自动获得新任务。通过图形连接工作区与事件，也能让 GitHub webhook 等外部信号触发工作。
- **工具调用与权限记录**：任务详情按输入、智能体和工具展示调用过程，可搜索并查看参数、返回结果及批准或拒绝状态。YOLO 模式支持自动批准请求，同时保留记录。
- **Whisper 本地转写**：在任务描述或回复中点击麦克风即可听写。首次使用下载浏览器模型，之后在设备上处理语音，不上传录音。

任务时间线记录每次状态变化，并统计工作、阻塞和等待输入的时长。工作区还支持消息发送倒计时，在送达智能体前可立即发送或取消；取消后原文与附件会回到编辑框。

## 怎么安装和使用 agentrq？

当前材料没有可核实的 DSH 安装命令，也没有确认 npm 包名，因此不能提供包安装指令。README 片段未包含部署命令、认证参数或连接配置文件位置，需要先查阅仓库完整文档，完成平台部署与智能体接入。

连接就绪后，可按以下顺序使用已说明的功能：

1. 打开工作区，创建任务并描述预期结果，将工作分配给智能体。接入后的智能体可通过 MCP 获取自己的任务。
2. 在列表或看板中跟进状态，通过任务对话回答问题，在出现权限请求时进行审批。
3. 打开任务详情的 History 标签，检查工具输入、输出和权限结果；结合状态时间线了解耗时与阻塞阶段。
4. 为重复工作设置执行日期或周期。需要串联多个阶段时，在工作流图中配置工作区订阅事件，以及完成任务后发出的事件。
5. 按需在工作区设置消息发送延迟。查找任务可用 macOS 的 `⌘K`，其他平台使用 `Ctrl+K`，搜索范围是当前设备已保存的任务副本。

## agentrq 报错怎么排查？

现有片段没有错误码说明或专门的安装故障解法。接入不显示时，可先进行通用检查：确认使用的 profile 名称、核对集成是否启用、重启 DSH，再查看版本信息与日志。这些是定位步骤，并非仓库承诺的特定修复方案。

任务停滞时，先检查调用历史与状态时间线，区分等待输入和阻塞阶段。权限请求被自动批准时，查看任务的 YOLO 开关，以及工作区或事件触发器对新任务的设置。搜索不到任务时，注意搜索器只查询设备上已保存的副本，并结合界面显示的搜索范围判断。
