## dsh-redteam-model 是做什么的？

dsh-redteam-model 是一个为 DSH 网页端提供安全研究模式预设与运行时组件的 DSH 插件。这个 DeepSeek Harness 插件合集并不是模型供应商；它通过预设组织角色、工作步骤、技能和参考资料，再由运行时组件记录任务进度和复核过程。本文只介绍防御性用途，包括源码审计、应急溯源和日志复核，不提供整套攻防组件的部署或启用步骤。

## dsh-redteam-model 核心功能

- **代码审计**：`code-audit` 面向白盒源码审查。已配置本机 Semgrep 时，可查看规则命中及其 Markdown、CSV 对账记录；命中是复核线索，不会直接成为漏洞结论。
- **应急溯源**：`incident-response` 面向 Windows 和 Linux 的应急响应与溯源。用它整理已有材料时，可以先写清受影响的系统、已观察到的现象和待确认的问题，再区分已核实事实与推测。
- **阶段记录**：阶段门组件会检查阶段记录的结构，并把判定写入 `gate-log.md`。结构通过只表示记录满足格式要求，不代表发现已经过人工复核。
- **会话留痕和成果筛选**：过程留痕组件可检索工具调用，成果页则支持按时间范围查看跨会话汇总。想知道某条结论是怎么来的，先看对应会话的调用记录；想回顾一段时间内的已登记成果，再到成果页筛选。

## 怎么安装和使用 dsh-redteam-model？

README 要求先准备 DeepSeek Harness 和 Node.js 22 或更新版本。网页端管理台要求 DSH 网页端至少为 `0.1.0-rc.6`，仓库记录的验证版本是 `0.1.1-rc.2`。以下步骤适用于已有部署，不需要启用整套运行时组件。

1. 打开 DSH 网页端设置，在 `Redteam Manager` 查看当前 profile 的操作记录。先确认所需预设是否已部署、对应的防御性组件是否可用，不要仅凭模式名称判断插件状态。
2. 从新建会话页面展开「专业安全模式」，按任务选择代码审计或应急溯源。复核源码时，把任务限定在指定仓库或文件范围内，要求说明判断依据和仍需人工确认的问题。
3. 如果已有 Semgrep 对账产物，先在任务工作区查看 `scan-reconcile.md` 或对应的 CSV，再对照源码复核。需要追查任务进度时，可看会话状态面板；需要了解某次调用发生了什么，则回到该会话的留痕记录。

## dsh-redteam-model 报错怎么排查？

- **新建会话看不到预设**：先确认打开的是预期的 DSH 网页端实例，再看管理台是否记录了成功部署。若只是模式复制状态没更新，先刷新页面；也可确认当前实例使用的 `DSH_HOME` 是否与部署时一致。
- **模式可见，但组件没有生效**：预设由同一 `DSH_HOME` 下的 profile 共享，插件声明则只修改当前 profile。确认正在查看正确的 profile，并核对相关组件是否启用；宿主插件安装、卸载或管理器自身更新后，需要重启 DSH 网页端。
- **管理台显示失败或中断**：在当前 profile 的近期记录中查看失败原因。管理台保留最近 50 条操作记录，重启时尚未完成的操作会记为中断失败。如果问题仍在，提交反馈时附上版本、模式名、预期与实际行为，以及相关的 `gate-log`、`enforce-log` 或会话输出片段。
