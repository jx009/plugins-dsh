## Wegent 是做什么的？

Wegent 是一个带有 DSH 插件标签的开源 AI 编码与团队协作工作台。个人可以在桌面端用 Codex 处理本地代码，团队则可以在同一个 Issue 中分派任务、查看执行记录、评审成果并交接。现有 README 介绍的是 Wegent 自身的使用方式，未说明如何将它装入 DeepSeek Harness，也未说明哪些能力可在 DSH 内直接使用。

## Wegent 核心功能

- **Issue 分派与交接**：用 Issue 写清目标，再交给成员、智能体或协作组。评审反馈和改派记录保留在原 Issue 中，下一位负责人可以接着已有方案和文件继续工作。
- **关联任务与成果回传**：从 Issue 创建 Wework 执行任务。运行完成后，先检查过程和结果，再挑选需要交回项目的文件或说明；分派了 Issue 不代表已经执行或交付。
- **Codex 本地编码**：Wework 是 Wegent 的桌面工作台，可以让 Codex 使用当前项目的代码、文件、命令和开发环境。检查工具活动、测试输出和文件差异后，再决定是否接受改动。
- **智能体配置与执行环境**：可为智能体组合模型、提示词、Skills、知识和工具。任务可交给本地设备、远程工作机或服务端托管的执行器；共享项目中要显式添加智能体。
- **个人替身（Beta）**：可以限定替身从哪些项目来源接收工作，并设置职责和处理策略。项目权限与操作审批仍然生效，执行过程有记录，需要人工判断的结果可以交回本人确认。

## 怎么安装和使用 Wegent？

目前可见的 README 没有给出 DeepSeek Harness 插件安装命令，npm 包名也未确认。如果你的目标是本地编码、团队协作或自托管，可以按以下路径使用 Wegent。

1. **在本地项目中运行任务**：从 GitHub Releases 下载 Wegent Desktop 安装包。启动后按应用提示配置模型，再添加或选择本地项目。描述需要分析、修改或验证的内容并创建任务，完成后查看命令输出、测试结果和文件差异。本地工作不需要登录 Wegent Backend。
2. **在共享项目中协作**：连接 Wegent Backend，创建或加入云端协作项目，再添加项目成员。需要 AI 执行时，手动加入智能体并设置模型与执行环境。在 Issue 中写清目标并分派，再从 Issue 建立关联任务。执行后回传选定成果，需要返工或交接时就在原 Issue 中留言。
3. **自托管 Web 与 Backend**：按照 README 的 Docker 独立部署方式启动。服务运行后访问 `http://localhost:3000`，在初始化页面设置管理员密码并配置模型。这一步部署的是 Wegent 服务，不会把插件装入 DSH。

## Wegent 报错怎么排查？

- **Issue 已分派，但看不到执行记录**：先检查是否从 Issue 创建了关联任务。分派只指定负责人；如果由 AI 执行，还要确认项目已添加智能体，并且模型和执行环境可用。
- **个人替身没有接单**：在 `My stand-in` 中检查项目来源授权、职责和处理策略，再确认模型配置与设备状态。自动处理仍受项目权限和操作审批限制，关机的设备不会继续执行任务。
- **在 DSH 中找不到 Wegent**：如果你已通过其他渠道确认安装方式并完成安装，先核对正在使用的 profile 和插件启用状态，再重启 DSH 并查看版本与日志。桌面端能打开或后端能访问，并不能说明当前 profile 已安装插件。
