## mem9 是做什么的？

mem9 是一个为智能体提供跨会话记忆的 DSH 插件。它以原生 DSH/Cordis 插件包的形式接入，把记忆的存储和检索交给服务端。只要新会话仍连接同一个记忆空间，即使重启 DSH 或换一台设备，也能检索之前保存的信息。

它适合需要反复回到同一项目的场景。例如，项目术语、已经确认的约定和长期偏好可以保存为记忆，后续任务需要时再查。这个 DeepSeek Harness 插件还可以与其他受支持的客户端共用一个空间，让不同智能体不必各自维护一份项目背景。

## mem9 核心功能

- **跨会话记忆**：记忆保存在服务端，而不是只留在当前会话中。换设备后连接原来的空间，就能继续查找已保存的内容。
- **多智能体共享**：DSH、OpenClaw、Claude Code 等受支持的客户端可以读取同一个空间的记忆。比如，一个客户端写入项目决定，另一个客户端接手任务时可以检索它。
- **混合检索**：结合语义搜索与关键词搜索。记得大意时可以按意思查，记得项目代号或术语时也可以用原词查。
- **记忆写入与管理**：DSH 集成提供记忆召回、智能写入和记忆工具，服务端支持保存、搜索、读取、更新和删除。也可以通过可视化面板检查和管理已保存的条目。

## 怎么安装和使用 mem9？

当前可见的仓库主 README 没有列出 DSH 安装命令，npm 包名也未确认。请先在 `mem9-ai/mem9` 仓库中打开 `dsh-plugin/README.md`，按 DSH 专用指南安装，不要套用 OpenClaw 或 ClawHub 的安装步骤。

1. **选择服务端。** 不想先搭建后端，可以使用托管 API `https://api.mem9.ai`。如果自托管，先按仓库的自托管说明初始化对应的数据库结构并启动 `mnemo-server`，再使用自己的服务地址。
2. **配置连接凭据。** 在启动 DSH 的环境中设置 `MEM9_API_URL` 和 `MEM9_API_KEY`，分别填入服务地址和对应空间的 API 密钥。自托管示例使用 `http://localhost:8080`，实际配置以运行 DSH 的环境能访问的地址为准。
3. **验证跨会话读取。** 启动 DSH 后，先用记忆工具保存一条不含敏感信息的测试内容，再开一个连接同一空间的新会话，用原关键词或换一种说法查找。如果要验证多智能体共享，再从连接同一空间的另一个受支持客户端检索这条内容。

## mem9 报错怎么排查？

- 先确认当前启动使用的配置档（`profile`）与安装插件时选择的一致，再检查插件是否已启用。修改配置后重启 DSH，确认启动进程读到了新的环境变量。
- 如果插件已加载但无法读写，检查 API 地址是否能从运行 DSH 的环境访问，并确认密钥对应的是该服务上的目标空间。如果只是查不到旧记忆，再核对读写两端是否连接同一个空间。
- 如果重启后仍有问题，记录 DSH 和插件版本，查看启动和调用时的日志，区分是插件未加载还是已加载但服务请求失败。分享日志前，先去掉 API 密钥等凭据。
