## MemOS 是做什么的？

MemOS 是一个提供持久记忆的 DSH 插件，帮助开发者让助手跨会话保留有用上下文，减少反复补充背景信息的需要。它在任务开始前自动召回相关内容，在成功交互后保留新经验，无需修改宿主核心。对需要持续理解用户偏好或历史任务的智能体，这提供了独立于当前对话的记忆能力。

作为 DeepSeek Harness 插件，它明确提供自动召回、后台采集、混合检索和本地 Memory Viewer。项目整体还涵盖知识库、多模态信息和工具记忆，但不能把这些通用能力直接等同于 DSH 中已经公开的配置项；当前 README 节选没有说明两者的完整对应关系。

## MemOS 核心功能

- **自动召回**：在任务开始前取回相关记忆，为后续执行补充上下文。适合需要延续既有信息的助手，而不是只依赖当前会话内容。
- **后台记忆采集**：成功交互后保留新经验，让记忆积累进入日常使用流程。节选未给出采集过滤规则，不应理解为每条消息都会保存。
- **混合检索**：DSH 接入介绍明确包含这一能力。README 在本地记忆核心的介绍中提到 FTS5 与向量检索，但没有列出该宿主的专用参数。
- **本地 SQLite 存储**：快速开始表格明确支持 DSH 本地接入，数据位于用户机器上，无需单独部署表格中的服务端基础设施。
- **本地记忆查看器**：Memory Viewer 用于查看记忆，便于检查保留的上下文。当前节选未提供启动命令、访问地址或具体操作说明。

## 怎么安装和使用 MemOS？

当前 README 节选没有 DSH 安装命令，仓库信息也未确认 npm 包名，因此这里不提供可复制的安装指令。不要把仓库名直接当成包名，也不要将其他智能体的插件命令用于当前环境。

1. 查看[完整 README 的插件章节](https://github.com/MemTensor/MemOS#memos-plugin)。DSH 接入提示指向该部分，应以其中的包名和专用配置步骤为准。
2. 选择接入路径。本地插件明确面向 DSH，采用设备上的 SQLite；更新说明也宣布了云端插件支持，但节选没有对应的配置细节。
3. 按完整文档完成安装和配置。快速开始只概括为 npm 安装加智能体专用设置，没有提供配置文件路径、字段名称或查看器启动方式，这些内容不能自行补写。
4. 配置完成后，用包含待保留背景的任务验证流程。成功交互后，通过查看器检查记忆，再发起相关任务观察是否召回。这个步骤用于验证接入，不代表每次交互必然生成某条记忆。

README 中的 Docker 命令部署的是独立 REST 服务，涉及 Neo4j 和 Qdrant，不是本地插件的安装步骤。仅为本地接入时，不要把自托管服务流程当成必经环节。

## MemOS 报错怎么排查？

节选没有列出 DSH 专用错误码或已知故障解法，可以先做通用检查：确认当前运行的 profile 与安装配置目标一致，确认插件已启用，修改配置后重启 DSH。

如果仍未出现预期的召回或采集，记录宿主与插件版本，并检查可用日志。安装阶段有疑问时，优先回到完整插件说明核对包名和接入步骤，不要靠更换猜测的包名解决问题。本地插件与自托管服务的存储、依赖不同，排查时应先明确自己使用哪条路径。
