## harness-mix 是做什么的？

harness-mix 是一个将 DeepSeek Harness 等编程智能体接入官方 Codex Desktop 界面的本地集成内核。它面向需要在多个智能体之间分配、接力和审查任务的开发者，让不同工具的执行结果出现在同一套桌面界面中。对搜索 DeepSeek Harness 插件的用户来说，它提供的是桌面集成能力；当前材料没有确认它可作为常规 DSH 插件加载。

项目注册了 18 个 Harness，包括 Codex、Claude Code 和 OpenCode。只有本机已安装且握手成功的工具才能真实运行。默认官方 Codex 会话仍直接连接官方 app-server；明确选择其他工具或协作模式后，独立 Host 才处理相应任务。模型、凭据、工具执行与权限审批继续由各 Harness 管理。

## harness-mix 核心功能

- **跨工具任务接力**：通过输入框接力入口或 `/switch`，选择继续执行、执行计划、独立审查或重新分析。交接保留脱敏检查点和证据追溯，便于后续任务接续。
- **多智能体团队**：输入 `#` 选择参与者，以标签管理成员；任意 Harness 都可以担任团队长。编排支持循环审查、子任务级联取消和超时处理，也可保存团队模板。
- **原生技能与 MCP**：技能管理覆盖 18 个原生目录，可拖入 `SKILL.md` 或整个文件夹。服务连接支持 stdio、Streamable HTTP、SSE 和自定义 Header，按 Harness 独立生效。
- **历史会话引用**：支持导入 Pi、Claude、Codex 和 CodeBuddy 原生历史，也能用 `#` 引用旧会话。引用先读取最近一页，智能体可通过只读工具按需获取更多消息和元数据。
- **健康与用量检查**：健康中心展示宿主状态、握手结果和崩溃报告，支持手动刷新与重探。用量中心按日、工具和模型汇总近 90 天的 token、花费及上报次数。

## 怎么安装和使用 harness-mix？

提供的 README 片段没有安装命令，因此此处不生成 DSH 安装指令。已知 npm 包名为 `@harness-mix/cli`，但包名本身不能确认桌面集成的安装流程。请先查看仓库中的 `docs/cross-platform.md`，核对安装方式与系统前提。

1. 准备桌面环境，并在本机安装需要使用的原生 Harness。macOS 和 Linux 已有源码构建及启动适配，完整桌面验收仍需在目标机器进行。
2. 在 Codex Desktop 的工具栏或输入框中找到集成入口，明确选择目标工具。DSH 的普通模式采用 Web Remote，协作模式采用 ACP。
3. 打开设置 → 健康，确认目标工具握手成功。注册表里有名称，不代表本机已经具备运行条件。
4. 在设置 → Skills 安装技能，在设置 → MCP 配置服务。登录、模型和审批仍按对应原生工具管理。
5. 开始任务后，用 `/switch` 发起接力，或通过 `#` 选择团队成员。需要复用分工时，在协作管理模板中设置成员，再从输入框的团队页选择模板并输入目标。

## harness-mix 报错怎么排查？

目标工具无法运行时，先确认本机安装，再到设置 → 健康检查握手结果，手动刷新或重新探测。宿主异常时查看崩溃报告，并记录版本与日志，帮助区分启动问题和连接问题。

失败回合会按原生错误信息归入连接、登录、额度、被拒或服务异常；不能判断时显示 `unknown`。根据界面提供的动作重试、登录或新建会话，登录按钮只会在工具确实支持时出现。

界面缺少功能时应核对支持矩阵。原生子代理卡片目前接通 16 个 Harness，Trae 和 Kiro CLI 暂未接入。macOS 或 Linux 启动异常则先检查跨平台指南中的桌面前提，不能仅凭平台标识判断完整桌面流程已经通过验收。
