## mirage 是做什么的？

mirage 是收录在 DSH 插件市场的智能体虚拟终端。它把智能体看到的命令行、存放数据的服务和实际执行命令的机器分开配置。对需要让智能体同时处理对象存储、聊天记录和邮件的开发者来说，可以先把这些来源挂载成不同目录，再用熟悉的命令查看和搜索，不必为每个来源切换一套操作界面。资料展示的是在应用内接入虚拟终端，未提供原生 DeepSeek Harness 安装步骤。

## mirage 核心功能

- **虚拟文件系统挂载。** S3、Slack、Gmail 和 Google Drive 等来源可以挂载到同一个目录树下。会话通过 `ls` 查看目录，也能用 `grep` 或 `find` 搜索多个挂载路径。
- **虚拟 CLI。** 受支持的 `slack` 等命令由虚拟终端处理，不要求在每个运行环境安装对应的程序。同一种工具还可以用不同名称注册，各自使用独立凭据。
- **命令路由。** 数据挂在哪里与命令在哪里执行，可以分开决定。Python 示例同时配置了进程内的 Monty 运行环境和 E2B 沙箱，并将涉及 NumPy 的命令交给后者处理。
- **会话权限。** 通过 profile 指定会话可见的路径和可执行的命令。也可以定义哪些命令需要审批，以及向智能体返回多少输出。
- **命令记录与追踪。** 项目会记录智能体执行的命令，并可将追踪数据发往 OpenTelemetry 后端。工作区还支持保存为快照。

## 怎么安装和使用 mirage？

当前 README 摘录没有给出 DSH 安装命令。应用接入可以参考仓库列出的 Python 和 TypeScript 快速入门，对应的软件包是 `mirage-ai` 和 `@struktoai/mirage-node`，不要把它们当作已经确认的 DSH 插件安装目标。

1. 按应用使用的语言选择快速入门。以文档中的 Python 示例为例，先在应用代码中创建 `Workspace`。
2. 在工作区中配置数据来源、挂载路径和挂载模式。示例把 S3、Slack 和 Gmail 放到各自的目录；需要在终端中调用服务命令时，再单独配置对应的虚拟 CLI。
3. 为会话定义 profile，明确要隐藏的路径和要禁止的命令。需要多个运行环境时，在工作区中配置机器及路由规则，然后用指定的 profile 创建会话。
4. 先从该会话执行只读检查。例如，用 `ls /s3` 确认能看到预期目录，再用 `grep` 搜索已挂载的数据源，确认智能体能访问需要的内容。

## mirage 报错怎么排查？

- **文件明明存在，却提示找不到。** 先核对挂载路径，再检查当前会话所用的 profile。README 的示例隐藏了 `/s3/secrets`，智能体读取其中的文件时看到的是文件不存在，而不是单独的权限提示。
- **虚拟 CLI 返回 `Permission denied`。** 先检查会话配置是否禁止了该子命令，不要看到权限报错就先更换服务凭据。示例中 Slack CLI 已注册，但发送消息的命令被明确禁止。
- **命令没有在预期的环境里执行。** 核对工作区中的机器配置和路由条件，再对照会话实际提交的命令。Python 示例按命令行是否包含 `numpy` 选择是否转到 E2B，因此应先确认实际运行的命令是否满足这个条件。
