## OpenBiliClaw 是做什么的？

OpenBiliClaw 是一个把本地个性化内容发现 Agent 接入工作区的 DSH 插件，帮助兴趣分散在多个平台的用户集中发现内容。主项目提供后端和浏览器扩展，DeepSeek Harness 插件客户端位于独立仓库 `whiteguo233/dsh-openbiliclaw`，使用时需区分这几个组件。

它根据跨平台使用、对话和反馈持续更新兴趣理解，再主动寻找内容。来源包括 B 站、小红书、抖音、YouTube、Reddit，以及自定义网站和 RSS。用户的喜欢、不感兴趣和聊天反馈会影响后续推荐，适合希望持续调整内容方向的人。

## OpenBiliClaw 核心功能

- **DSH 常驻第四栏**：在工作区展示推荐、内容库、对话、画像和设置，让内容发现与日常智能体任务放在同一界面中。
- **Agent Bridge 工具**：客户端注册 22 个工具，支持智能体读取推荐、回答探测并参与闭环学习。当前 README 摘录未列出具体工具名及调用参数。
- **跨平台内容发现**：结合用户兴趣到多个来源主动寻找内容，也覆盖开放 Web，减少兴趣信息被不同平台分散保存带来的割裂。
- **反馈驱动画像**：从事件、偏好到更深层的兴趣理解逐步构建画像。对推荐的明确反馈和对话内容都能参与后续调整。
- **本地优先存储**：数据默认留在本机 SQLite；向量计算可选云端或本地模型，部分安装包预置 BGE-M3。存储位置与模型运行位置需分别理解。

## 怎么安装和使用 OpenBiliClaw？

当前材料未提供 DSH 安装命令，也没有确认 npm 包名，因此此处不生成命令。客户端安装入口为 `whiteguo233/dsh-openbiliclaw`，具体安装和连接配置以该仓库说明为准。

1. 安装浏览器扩展：从 Chrome 应用商店安装，或在项目最新 GitHub Release 下载 ZIP 手动安装。商店版可能比发布包晚几天。
2. 部署本地后端：在同一发布页下载 macOS `.dmg` 或 Windows `.exe`。Apple Silicon 与 Windows 可选精简版或 `-with-embedding` 版，Intel Mac 提供精简版；本地向量模型也可按需下载。
3. 打开本地界面：访问 `http://127.0.0.1:8420/web`，先确认后端可以访问，再继续连接客户端。
4. 连接内容来源：在装有扩展的浏览器中登录所需平台。B 站是默认初始化来源，也可改选其他支持的平台；需要账号状态的来源仍依赖浏览器扩展。
5. 使用 DSH 客户端：完成独立仓库要求的配置后，在第四栏查看推荐、管理内容和查看画像，通过喜欢、不感兴趣或对话表达偏好。

若使用 TikTok 或 Instagram，需在「设置 → 来源」手动开启。两者需要海外网络，后端请求沿用后端网络或代理配置，浏览器任务使用浏览器自身代理，排查时应分别检查。

## OpenBiliClaw 报错怎么排查？

如果 DSH 中没有出现客户端，可先做通用检查：确认当前 profile 名称、插件是否启用，重启 DSH，再查看版本和日志。当前摘录没有给出客户端专用错误码、连接字段或配置文件路径，具体字段应查客户端仓库说明。

如果内容来源不可用，检查来源是否开启，以及需要登录的平台是否已在装有扩展的浏览器中登录。涉及 TikTok 或 Instagram 时，再核对上述网络条件和两端代理配置。

如果安装后缺少新功能，先比对 GitHub Release 的版本。README 说明 Gitee 提供源码镜像，123 云盘仍保留 `v0.3.213` 历史文件；获取当前桌面安装包应以最新 GitHub 发布页为准。
