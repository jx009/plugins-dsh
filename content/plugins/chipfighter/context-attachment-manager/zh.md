## context-attachment-manager 是做什么的？

context-attachment-manager 是一个减少多图会话中旧图重复发送的 DSH 插件。当一段对话陆续加入多张截图、视频关键帧或扫描件时，每轮请求都带上之前的原图，会让请求体越来越大。这个插件给图片分配编号，用简短占位符代替请求里的旧图。模型需要重新查看某一张时，再按编号取回原图，而不是把所有旧图一起发出去。

它适合在同一段对话里反复对照素材，例如先讨论几张分镜，再回头核对第一张的画面细节。插件在本地运行，不删除原图或聊天记录；请求仍发往智能体原来使用的服务。仓库已在 Codex 和 Claude Code 上测试，DeepSeek Harness 适配器则列为支持自动选择，但尚未经过实机测试。

## context-attachment-manager 核心功能

- **自动选择旧图**：图片出现后的下一轮，插件可用占位符代替原图。占位符带有 `IMG-001` 一类的编号，也能保留一行图像描述和你对这张图的备注，让模型知道该回取哪一张。
- **按编号取回原图**：模型需要核对旧截图上的文字或画面细节时，可以按编号请求原图。回取的图片附在当前轮末尾，之前的占位符留在原处。
- **会话压缩后继续回取**：按项目设计，压缩上下文后仍可通过图片编号找回原图，保留下来的描述和备注可用于区分相似素材。
- **减少对提示词缓存的扰动**：占位符写入后保持不变，便于后续请求复用较早的会话前缀。首次替换图片时，该轮中位于替换点之后的内容仍需重新处理一次，并不是每次请求都能完整命中缓存。

## 怎么安装和使用 context-attachment-manager？

当前 README 未提供可直接执行的 DSH 安装命令，仓库信息也没有确认 npm 包名。安装时打开仓库的 `INSTALL.md`，从 `other-agents` 小节查找 DeepSeek Harness 的适配说明，不要用仓库名猜测安装命令。

1. 按适配说明安装后重启 DSH，确认当前会话使用的 profile 与安装时选择的一致，并检查插件是否已启用。
2. 从默认的自动选择开始使用。README 没有列出 DSH 专用面板或额外配置项；Codex 的侧栏入口和 Claude Desktop 的 `/cam` 不适用于这里的配置流程。
3. 用一段短会话试用：先发两张容易区分的截图，继续发一条消息，再请模型回看第一张上的某个细节。如果对话中已有图片编号，可以直接引用它，避免只说“前面那张”而指错图。

## context-attachment-manager 报错怎么排查？

如果装完后看不出变化，先核对当前 profile、插件启用状态以及安装后是否重启过 DSH。排查时不要只看刚上传图片的那一轮：文档描述的替换发生在图片出现后的下一轮，可以继续发一条消息再观察。

如果模型无法按编号回取旧图，先在短会话里检查普通追问能否回取，再和压缩后的表现对比。仍有问题时，记录 DSH 和插件版本，查看启动及出问题时的会话日志。README 未列出 DSH 专用错误码或修复步骤，也没有提供该适配器的实机测试结果；反馈时附上版本、操作顺序和相关日志，比套用其他智能体的面板说明更有用。
