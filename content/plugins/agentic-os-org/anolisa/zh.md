## ANOLISA 是做什么的？

ANOLISA 是通过组件、适配器和插件为智能体增加运行时能力的系统软件栈。对于寻找 DSH 插件集成方案的开发者，它提供上下文管理、安全约束、工作区恢复和执行观测等能力方向。当前 README 介绍了通用 harness 接入方式，但没有给出专用的 DeepSeek Harness 插件安装流程。

它建立在现有操作系统内核和基础设施上，支持从预装镜像开始、向现有系统安装组件，或为已有智能体接入无界面系统能力。选择适配器接入时，可以继续使用原有界面、模型账号和工作流程。ANOLISA DSH 运行时集成应从项目的安装与适配器指南开始核实。

## ANOLISA 核心功能

- **Tokenless 输出压缩**：缩短冗长的工具返回结果，减少上下文占用。文档提供压缩与 Token 用量对比示例，没有给出固定节省比例。
- **持久记忆**：让智能体检索并复用跨会话信息，减少重复读取，帮助保留对当前任务有用的内容。
- **OS Skills 技能发现**：智能体可以查阅系统指令，发现并读取任务所需技能。cosh 终端还支持通过自然语言调用工具和技能，同时保留熟悉的 Shell 体验。
- **安全约束与工作区恢复**：安全策略和底层隔离机制限制智能体行动；工作区快照支持检查文件变化，并按需回滚。
- **AgentSight 执行观测**：查看模型调用、工具调用、执行轨迹和 Token 用量，用于调查任务失败及分析运行成本。

## 怎么安装和使用 ANOLISA？

提供的 README 没有 DSH 安装命令，仓库信息也未确认 npm 包名，因此不能生成可直接执行的安装指令。先查阅项目给出的安装与适配器集成入口：`https://agentic-os.sh/docs/user-guide/getting-started/installation/`。

1. 选择部署方式。继续使用现有 harness 时，查看适配器接入流程；需要独立运行环境时，查看预装镜像目录或系统软件包安装指南。
2. 核对平台条件。README 在扩展现有操作系统的流程中明确提到受支持的 Linux 系统，平台标识还列出 macOS；具体组件要求以安装指南为准。
3. 按需求安装组件并配置服务。压缩、记忆、安全、快照和观测分别涉及相关能力，不能仅凭接入入口就认定全部可用。当前摘录没有提供配置文件路径或适配器参数。
4. 完成适用的集成后，在原有智能体界面中继续工作。如果选择 cosh 作为终端入口，则按首次使用指南配置模型访问和相关服务。
5. 验证已启用能力。通过 Tokenless 示例检查工具输出与用量变化，通过 AgentSight 示例查看执行记录；依赖快照或安全功能前，先完成对应组件配置。

## ANOLISA 报错怎么排查？

README 未列出 DSH 专用错误码或修复命令。可以先进行通用检查：确认使用的 profile 名称正确，相关适配器或插件已启用，并在配置变更后重启 DSH。

接着核对组件版本，查看 harness 与相关服务的可用日志，并对照安装指南检查平台条件和服务配置。如果没有看到压缩结果、快照或执行记录，先确认负责该能力的组件是否已安装并配置。进一步求助时，整理失败的具体能力、版本与日志内容，便于缩小问题范围。
