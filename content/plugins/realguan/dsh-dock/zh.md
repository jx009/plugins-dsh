## dsh-dock 是做什么的？

dsh-dock 是一个集中管理工作台、扩展和运行环境的 DSH 插件管理桌面工具。它面向需要维护多个配置环境、安装社区能力和排查启动问题的开发者，将常用操作收进独立控制中心。作为 DeepSeek Harness 插件生态的管理入口，它通过官方 CLI 与文件契约协作，不修改上游源码。

应用基于 Tauri v2、Rust 和 React 19，覆盖 Apple Silicon 与 Intel Mac、Windows 及 Linux，提供中英文界面。Windows 支持本地与 WSL2 两种运行方式，Linux 提供 deb、rpm 和 AppImage 包。

## dsh-dock 核心功能

- **多工作台管理**：创建、克隆、重命名、删除和启动隔离工作台，查看运行状态与插件数量。克隆时排除 `node_modules` 并改写包名，运行中的工作台会锁定以避免误改。
- **社区插件市场**：README 标注收录 3,400+ 插件，可按分类、关键词检索，并选定目标工作台安装。支持 npm、GitHub 仓库与 HTTPS tarball，后台队列展示安装进度。
- **MCP 配置**：填写命令、参数和环境变量，在当前工作台与全局范围间切换。兼容 `stdio` 和 `streamable-http`，支持探测工具与资源。
- **模型凭据管理**：集中录入 DeepSeek、OpenAI、Anthropic 等服务的密钥，界面以掩码展示。Raw 模式可编辑 `.credentials.yaml`，Unix 下保存时强制使用 0600 权限。
- **健康诊断与日志**：查看 Node、pnpm、DSH 的版本、路径和就绪状态。可复制诊断报告，切换壳日志与运行时日志，按关键词筛选并追踪尾部 600 行。

## 怎么安装和使用 dsh-dock？

提供的 README 没有 Dock 自身的安装命令，也没有确认 npm 包名，因此应通过仓库 Releases 入口下载对应平台的桌面包。文中通用的插件安装语法用于管理扩展，不能当作本应用的安装命令。

1. 安装并首次启动应用。引导流程会检测并补齐缺失或版本不符的运行组件，无需提前安装 Node.js、pnpm 和 DSH。
2. 在启动中心选择工作台，或进入「控制中心 → Profile 列表」新建。可设为默认启动；未设置时出厂工作台为 `web`，多个可启动工作台时可通过启动中心记住选择。
3. 打开「插件中心」搜索扩展，确认目标工作台后安装。回到工作台的插件列表，查看版本、运行态徽标及启停开关；默认筛选显示社区插件。
4. 在工作台详情的 MCP 页签配置服务器，先确定生效范围，再填写参数并探测能力。需要修改 `cordis.patch.yml` 时使用 Patch 页签，覆写前会自动备份。
5. 在「系统控制台 → 模型凭据」配置服务商密钥。引擎设置在 `settings.yaml` 编辑面板中管理，保存前会提示确认并备份。

## dsh-dock 报错怎么排查？

插件未显示或未运行时，先确认 profile 名、列表筛选条件及启用状态，再查看运行态徽标。若界面提示需要重启，重启 DSH 后复查；仍有异常则进入运行日志定位相关记录。

终端与桌面端版本不同，可先查看健康大盘中的实际路径与版本。Dock 自管引擎，不通过 `PATH` 接管全局安装的实例，不能只凭终端结果判断桌面运行环境。

`desktop` 是官方保留工作台，无法在 Dock 中启动、重启、设为默认、重命名或删除。插件与 MCP 内容仍可管理；需要启动相同配置时，可复制为其他名称。

若 60 秒内连续崩溃三次，守护机制会停止自动重启并显示日志片段。先检查失败卡片，再结合运行日志和诊断报告排查。关闭主窗口只会隐藏应用，可从托盘或 macOS 菜单栏唤回；彻底结束需使用其中的「退出」。
