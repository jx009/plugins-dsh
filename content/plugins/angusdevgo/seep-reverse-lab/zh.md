## Seep-Reverse-Lab 是做什么的？

Seep-Reverse-Lab 是一个用于多平台静态分析和客户端授权审查的 DSH 插件。它把二进制分析工具和技术知识库接入会话，适合查看有权审阅的构建产物、梳理程序结构，并整理供开发团队复核的审查记录。本文介绍的是只读检查和防御性审阅，不涉及绕过授权或运行漏洞验证脚本。

如果你关注的是 CWE-602，首先要分清两个问题：客户端是否根据权限改变界面或功能入口，以及服务端是否对受保护的操作独立授权。前者可以从客户端材料里找线索，后者不能仅凭反编译结果下结论。把这两类发现分开记录，能避免把界面行为误写成已确认的服务端漏洞。

## Seep-Reverse-Lab 核心功能

- **多平台文件识别**：覆盖 Windows PE、Android APK 和 Linux ELF 等格式。初次接手构建产物时，可以先确认格式和架构，再选择需要审阅的部分。
- **统一的静态分析入口**：通过 MCP 汇集 Radare2、JADX 和 Apktool 等工具。查看 APK 时，可以先读清单和代码结构，为后续的人工审阅缩小范围。
- **反编译输出精简**：部分工具提供完整、折叠或摘要视图，不必把整个输出都带入会话。先看结构，再展开与审查问题直接相关的代码段。
- **知识库检索**：项目收录技术记录和脱敏案例，可用于了解授权设计中的常见问题。参考资料用于解释风险背景，不能替代当前版本的证据。

## 怎么安装和使用 Seep-Reverse-Lab？

本页不提供一键部署命令。开始前先区分仓库 `INSTALL.md` 中的两个框架入口；Pi Agent 的说明不能当作 DeepSeek Harness 的配置说明使用。

1. 确认平时启动 DSH 使用的配置档，也就是 `profile`，并在同一配置档中检查插件是否已启用。不要用另一个配置档的插件状态判断当前会话。
2. 如果环境中已经配置了该插件，核对安装时登记的工作台路径是否仍指向实际目录。README 说明插件会在运行时挂载 MCP 服务，因此插件可见与工具可用是两个不同的检查项。
3. 用已有环境进行只读检查时，先选取自己有权审阅的构建产物。例如，可以要求：“只列出这个 APK 的文件结构、清单组件和架构信息，不运行样本，也不修改文件。”如果只需概览，可以要求用摘要呈现结果。
4. 整理结果时分开写明已观察到的事实和待核对的问题。涉及客户端授权的疑点，交给维护者对照服务端实现确认，并注明审阅的构建版本，避免把不同版本的发现混在一起。

## Seep-Reverse-Lab 报错怎么排查？

- **插件不显示**：核对当前配置档与启用状态，然后重启 DSH，再确认插件是否出现。先排除启动时用错配置档，再检查其他原因。
- **插件可见但工具不可用**：检查工作台目录是否被移动，并查看启动日志中与插件加载和 MCP 挂载有关的记录。优先记下最早出现的异常，不要仅凭后续的失败信息猜测原因。
- **问题持续出现**：记录 DSH 和插件版本、使用的配置档以及相关日志片段。分享信息前移除凭据、本机敏感路径和不宜公开的样本内容。
