## dsh-purge 是做什么的？

 dsh-purge 是一个通过修改本地宿主策略来做安全评估的 DSH 插件。它面向需要区分宿主限制与模型拒答的开发者：会话没给出预期结果，不一定是模型作出了拒答，也可能是 DeepSeek Harness 在提示词处理、审批或工具调用环节施加了限制。这个项目不提供新的模型服务，也不是只改变界面的主题。

`mmparko/dsh-purge` 是上游 `YuJunZhiXue/dsh-purge` 的镜像。这份 README 标注的版本是 `1.1.71`，同时说明上游已暂停维护，不保证适配新版宿主。查阅归档资料时，应把镜像保留的历史版本和当前仍受支持的版本区分开。引用或二次开发时，署名来源见 README 的署名章节。

## dsh-purge 核心功能

- **补丁状态查看。** 会话标题旁的插件入口会打开侧栏，Clean 页面按组显示补丁状态。检查已有环境时，先看这里报告了哪些本地改动，不要仅凭插件名称是否出现在界面上来判断宿主状态。
- **官方双端独立配置。** 官方网页端 `dsh web` 使用 `web`，README 指定的官方桌面 EXE 使用 `desktop`。两端虽在同一台机器上运行，仍要分别查看各自的配置和状态。
- **本地宿主策略修改。** README 将修改范围限定在本机官方 `@deepseek-ai` 软件包与本地配置，不直接修改 Harness 源码树。只修改本地文件不等于只调整界面，相关变更涉及审批、沙箱策略和工具限制。
- **还原与卸载。** Clean 页面分别列出了 Restore 和 Uninstall。接手已有环境时，先确认要处理的是宿主改动还是插件本身，不要把两个入口当成同一个操作。

## 怎么安装和使用 dsh-purge？

本页提供兼容性说明和已有安装的检查方法，不提供用于绕过宿主策略的安装或启用步骤。

1. **核对宿主版本。** 该发行版面向 DSH 0.2，README 明确列出的官方桌面版本是 `0.2.0-rc.2`。更早的宿主需要匹配的旧版插件，不能仅凭版本号更新就判断兼容；社区桌面版也不在维护范围内。
2. **确认运行环境。** 文档列出的基本要求是 Node.js 18 或更高版本。Windows 下避免闪窗另有 Node.js 22 或更高版本的要求，不要把后者当作所有环境的最低版本。
3. **先查 profile，再查补丁状态。** 网页端看 `web`，官方桌面端看 `desktop`。README 区分加入插件与修改宿主：即使某个 profile 已列出这个 DeepSeek Harness 插件，也不能据此认定宿主已发生改动。

## dsh-purge 报错怎么排查？

- **一端看得到，另一端看不到。** 先核对当前运行的是官方 Web 还是官方桌面端，再确认查看的是相应的 profile。只检查一端，无法确定另一端是否存在插件或本地改动。
- **升级后表现不同。** 记录宿主、插件和 Node.js 的版本，再查看日志。上游没有承诺支持新版 DSH，不要因为会话表现变化，就直接归因于模型拒答或某个固定错误码。
- **不确定旧环境是否还留有改动。** 在受影响的 profile 中查看 Clean 页报告的补丁状态和 Restore 入口。如果两端都用过，就分别核查，不要把一个 profile 的结果当成整台机器的状态。
