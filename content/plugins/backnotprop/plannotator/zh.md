## plannotator 是做什么的？

plannotator 是一个为智能体提供浏览器批注和代码审查界面的 DSH 插件。智能体提出计划、提交待审阅的文档或完成改动后，你可以在本地浏览器里标记具体位置，写下意见，再把反馈发回智能体。比如，审阅实现计划时，可以直接圈出不该改动的模块；验收代码时，则可以在差异中指出遗漏的边界条件。

这里有两类常用任务：动手前用计划模式确认范围和做法，动手后用代码审查核对实际改动。如果要检查的是需求文档、原型或智能体上一条回复，也可以直接批注对应材料，不必先把问题改写成一段聊天消息。

## plannotator 核心功能

- **计划和文档批注**：可以在计划、规格、Markdown 文档和智能体消息的具体位置留言。计划模式由宿主钩子触发，接入后不需要为每份计划单独输入打开命令。
- **本地与远程代码审查**：既能查看未提交的本地改动，也能审阅 GitHub 拉取请求和 GitLab 合并请求。你可以在差异中评论或提出代码建议，再把意见发回智能体。
- **大型改动导览**：在代码审查界面启用导览后，智能体会把差异按主题分章，优先呈现主要改动。每章把简短说明和实际差异放在一起，方便边读边核对。
- **HTML 与本地站点批注**：可审阅渲染后的文件，也可通过本地代理打开正在运行的站点。查看实际页面时仍可使用热重载，适合检查布局与交互。
- **收件箱集中回复**：Inbox 把多个智能体提出的问题、发来的文件和审查请求放在同一个本地窗口。你可以稍后处理，回复会回到提出请求的会话。

## 怎么安装和使用 plannotator？

当前 README 摘录没有提供 DSH 安装命令，仓库信息也未确认 npm 包名，因此没有可直接复制的安装指令。项目列出了对 DeepSeek Harness 的支持，但其他宿主和终端工具的命令不能替代这里的安装步骤。

1. 先查阅项目面向 DSH 的接入说明，确认当前版本应使用的接入方式。在你实际启动 DSH 所用的配置档案中完成设置；所给资料未注明配置文件路径或字段名。
2. 接入后，先让智能体生成一份简短的实现计划。审阅页打开后，在对应段落留下意见，发送反馈，再回到原会话查看智能体的回应。用小任务验证一轮，比直接拿大型改动测试更容易判断问题出在哪一步。
3. 已具备项目命令行工具时，可以先用 `plannotator inbox --help` 查看收件箱用法，再用 `plannotator inbox` 打开窗口。README 另给出了通过 `plannotator inbox mcp` 接入其他智能体的方式；这不是 DSH 插件安装命令。

## plannotator 报错怎么排查？

如果生成计划后没有打开浏览器，先确认当前会话加载的是你完成设置的配置档案，并检查集成是否已经启用。重启 DSH 后生成一份新计划，确认问题出在新任务上，而不是只查看接入前的旧会话。

如果命令不可用或反馈没有回到预期会话，核对当前 DSH 与已安装组件的版本，并查看触发审阅和发送反馈时的日志。尤其要区分宿主内命令和终端命令：README 为 Codex 等环境单独说明了调用方式，其他宿主的语法不能直接当作 DSH 的用法。
