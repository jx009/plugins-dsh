## dsh-reverse-skill 是做什么的？

 dsh-reverse-skill 是一个将逆向工程与安全研究技能文档接入宿主技能系统的 DSH 插件。它使用 Cordis 封装上游项目，共收录 88 份 `SKILL.md`：领域技能目录有 46 份，CTF 赛道目录有 42 份。这个数字指的是文档数量，不是可独立运行的工具或子智能体数量。

这款 DeepSeek Harness 插件的主要作用，是让宿主发现这些文档并按需读取，而不是另行提供分析工具。仓库也包含具有双重用途的渗透测试资料和辅助脚本。评估时可先阅读仓库根目录的 `DISCLOSURE`，区分包内资料、外部依赖和宿主授予的权限。

## dsh-reverse-skill 核心功能

- **递归发现技能文档**：插件遍历两个随包分发的技能目录，嵌套子目录也在扫描范围内。维护者调整目录内容后，不必另外同步一份手写清单。
- **按需读取正文**：技能提供器将列举候选项与读取正文分开。注册时使用文档头部的名称、描述和用户调用标记，而不是仅凭文件夹名称推断技能信息。
- **规范文本格式**：扫描器在读取时处理 UTF-8 BOM 和 CRLF 换行。仓库的测试也覆盖这两种格式，检查相关文档是否会被漏掉。
- **保留技能路由文档**：上游路由文档被放入与注册名一致的子目录。这个调整解决的是目录命名问题，不代表上游的子智能体也被移植到了宿主。

## 怎么安装和使用 dsh-reverse-skill？

项目支持的分发渠道是 GitHub。`main` 会随仓库更新，发布标签则用于标识固定版本；GitHub 版本随仓库提供预编译产物。npm 上的历史包不适用于当前版本。本页仅说明分发和配置检查，不提供整包部署或渗透测试调用步骤。

1. **确认配置归属**：检查现有环境时，先确认正在使用哪个 profile。浏览器界面通常使用 `web`；桌面端由应用管理 `desktop`，应在应用内的插件管理器核对状态，不要用浏览器的配置推断桌面端状态。
2. **区分插件名与包名**：仓库的 `cordis.patch.yml` 声明了插件接入方式，Cordis 配置中的插件标识是 `reverse-skill`。带作用域的包名可以出现在配置引用中，但这不代表 npm 安装渠道仍然可用。
3. **核对能力边界**：上游 `agents/*.yaml` 不在插件支持范围内，文档引用的 MCP 服务也不随包提供。技能正文中的工具限制字段不会被宿主强制执行，实际权限需要在宿主层单独检查。

## dsh-reverse-skill 报错怎么排查？

- **安装预检失败**：先确认报错是否来自 npm 上的历史 `1.0.x`。旧包声明的 `dsh-skill` 依赖与当前版本不兼容，失败发生在写入配置之前，重复尝试同一个裸包名不会解决问题。
- **界面里看不到插件**：先核对当前 profile 和启用状态。若配置刚发生变更，重启应用或重载 Web 界面，再查看生效配置和启动日志，区分配置未加载与插件未启用。
- **技能数量少于预期**：确认当前环境显示的是插件注册结果，还是本地 preset 的发现结果。后者只检查直接子目录，漏掉嵌套文档不等于仓库缺少这些文件。
- **文档提到的能力不可用**：如果缺少的是外部 MCP 服务或上游智能体，先对照插件的支持范围。这两类内容并未随包提供，不能仅凭文档中的引用判断它们已经加载。
