## Autoloom 是做什么的？

Autoloom 是基于 DeepSeek Harness、集成 Aegis 工程治理的 AI 编程桌面客户端。它帮助开发者在执行中检查变更必要性、质疑实现假设，并依据需求和验证材料审查交付。对于寻找 DSH 插件的用户，需要先明确安装形态：它使用独立桌面安装包，同时保留 Cordis 插件机制。

项目目标、约束和关键决策会随项目保留，运行时维护关键操作的前置条件、任务状态与执行证据，减少反复提醒智能体先调查、再修改的负担。当前产品处于 Beta，基于上游 `dsh-v0.1.1-rc.2` 构建，并纳入部分后续可靠性修复，采用自己的版本和发布节奏。完全自动化开发仍是目标。

## Autoloom 核心功能

- **Aegis 开发治理**：任务开始时检查目标、事实、已有能力和约束，判断是否需要变更。修改前审视职责重复、多余层次和维护负担，并考虑可能推翻方案的反例。
- **交付证据审查**：记录结果前，对照需求、实际执行与验证材料，区分已完成和未验证的内容。执行失败后，要求依据观察结果进行因果诊断。
- **治理影响记录**：获准的项目修改执行前，会话可显示折叠的 Governance impact 行，说明治理方法如何影响这次具体操作。面向用户的字段跟随请求语言，完整记录可供查看。
- **项目决策与偏好**：已记录的关键决策发生变化时，会给出具体差异供审查。支持配置测试优先偏好和代码复杂度阈值，以反映项目要求。
- **本地与远程工作区**：支持本地项目及通过 SSH 连接的 Linux x64 项目，提供文件、代码差异、命令日志、预览和停靠式交互终端。内置公共 Parallel/Exa MCP 服务提供网页搜索，无需额外的搜索密钥。

## 怎么安装和使用 Autoloom？

所给 README 没有 DSH 安装命令，也没有确认的 npm 包名，因此应使用文档提供的桌面安装流程：

1. 前往仓库 Releases 页面，下载 Windows x64 安装包 `Autoloom-<version>-win-x64.exe`。
2. 安装并启动客户端，在设置中添加模型提供商和 API key，然后选择默认模型。
3. 打开已备份的测试项目，从范围明确的小改动开始，便于检查执行过程与结果。
4. 查看代码差异、命令日志及验证材料；若项目已记录的关键决策发生变化，审查对应差异。
5. 如需连接远程项目，先阅读仓库 Beta 说明中的环境要求，再使用 SSH 工作区。

客户端免费，模型用量由所选提供商计费。目前桌面端仅提供 Windows x64，macOS 和 Linux 版本仍在计划中。摘录确认可以配置测试优先偏好与复杂度阈值，但没有给出这些选项的具体设置路径。

## Autoloom 报错怎么排查？

所给 README 摘录没有列出具体错误码或专项修复步骤。遇到异常时，先确认客户端版本，查看相关任务的命令日志；重启客户端后，用范围较小的任务复现问题，保留实际执行结果。

模型调用异常时，核对设置中的提供商、API key 和默认模型。远程工作区异常时，对照仓库 Beta 说明检查环境要求；当前摘录未包含完整要求，不能据此推断依赖或最低版本。

若问题出在任务执行或交付结果，结合需求、代码差异和验证材料定位原因。治理记录能说明执行过程，但不能单独证明修改正确；仍应以实际代码、执行结果和验证证据判断是否完成。
