## dsh-purge-plus 是做什么的？

 dsh-purge-plus 是一个修改宿主默认安全策略、并提供状态查看与回滚功能的 DSH 插件。它是 Purge Community 的独立维护分支，不只是一个提示词编辑器：宿主改动涉及审批和沙箱，可能改变工具执行前的确认流程及其访问边界。本文聚焦版本兼容性、现有安装的状态检查和故障恢复，不提供解除这些防护的操作步骤。

README 介绍的插件版本是 `1.6.1`。仓库描述将 `#119` 宿主崩溃和 `toolFilter` 预设注册失败列为此分支的修复项。排查时要分开记录 DSH Desktop 版本和插件版本；两者不是同一个版本号，单看其中一个不足以判断当前组合是否在回归范围内。

## dsh-purge-plus 核心功能

- **桌面版本适配**：README 记录了 macOS 上 `0.2.1-rc.1` 和 `0.2.1-rc.2` 的回归结果。Windows 和 Web profile 保留相关代码，但没有端到端验收记录。
- **宿主状态查看**：从左侧栏打开 `Purge`，在状态页核对宿主版本、兼容级别和插件版本。需要区分整体状态与某一条补丁的状态时，可以展开补丁明细。
- **提示词与规则管理**：面板为提示词、规则和技能分别提供入口。查看现有设置时，先分清要核对的是提示词正文、规则条目，还是 DSH 技能目录。
- **快照与回滚**：README 说明安装、应用或回滚前会创建快照。只撤销宿主补丁与恢复旧版插件是两项不同的操作，应按需要选择。
- **最近动作审计**：应用、回滚和开关变更会写入 `audit.jsonl`，也可以在面板的“最近动作”中查看。出现异常时，先核对故障前发生过哪些变更。

## 怎么安装和使用 dsh-purge-plus？

README 没有提供适用于桌面 profile 的 DSH 安装命令，因此本页不列安装指令。桌面 profile 由 Electron 应用管理，不能把面向 Web profile 的命令套到桌面环境里。在评估是否安装前，先确认操作系统、当前 profile 和宿主版本；不要把其他平台存在安装入口误读为已经通过兼容性验证。

如果当前环境已安装，可以按以下顺序检查配置和状态：

1. 在 DSH 左侧栏打开 `Purge`，进入“状态”页，核对页面顶部的宿主版本、兼容级别和插件版本。
2. 要确认现有配置的位置，可分别查看“提示词”“规则”和“技能”页；更新和备份入口在“更多”中。仅查看状态不需要点击“应用”。
3. 如果是在定位一次变更后的异常，先查看“最近动作”，再决定是撤销宿主补丁，还是恢复插件备份。

## dsh-purge-plus 报错怎么排查？

- **左侧栏找不到面板**：先确认打开的是预期的 profile，检查插件是否启用，然后完全退出并重开 DSH。仍未出现时，记录宿主与插件版本，查看启动日志。
- **桌面提示 profile 由 Electron 独占**：这不是 npm 包名拼写错误，而是桌面环境不接受普通的插件添加流程。不要用切换命令参数的方式把 Web 安装流程套到桌面 profile 上。
- **宿主改动后出现异常**：只需撤销宿主补丁时，README 给出的命令是 `purge-community revert`；要回到某个插件备份版本，则用 `purge-community rollback <backup-id>`。如果 macOS 上应用已经打不开，README 还记录了使用 `app.asar.bak` 恢复原 `app.asar` 的办法，前提是该备份仍在。
- **官方更新后出现 `app.asar` 提示**：README 将这一现象列为宿主更新后可能发生的变化。先核对更新后的版本是否仍在已验证范围内，不要仅凭之前的兼容结果继续修改新版宿主。
