## awesome-ai-plugins 是做什么的？

awesome-ai-plugins 是一个用于查找 DSH 插件的跨平台目录，本身不是可安装的插件。仓库由社区维护，除了 DeepSeek Harness，也收录面向 Claude Code、Codex、ChatGPT、Gemini CLI 等客户端的扩展。每个条目的目标客户端可能不同，能在目录里找到，并不代表能直接在你正在用的客户端里运行。

如果你正在找某项能力，可以先用目录缩小范围，再到候选项目的仓库确认它支持什么、如何接入。即使同一项目支持多个客户端，也应找对应的安装说明，不要把其他客户端的命令当作 DSH 命令。

## awesome-ai-plugins 核心功能

- **按客户端浏览**：README 在社区插件部分设有 DeepSeek Harness 专区。只想找当前客户端能用的扩展，可以从这里开始；在其他分区发现候选项时，先核对原项目的兼容性说明。
- **按扩展类型查找**：目录收录客户端专用插件、可单独安装的 Agent Skills 和 MCP 服务器。先看条目属于哪一类，再找对应的安装和配置说明，不要假设它们使用同一种接入方式。
- **在注册表搜索**：不想逐段浏览时，可从 README 进入 HOL 插件注册表，按项目名或需要的能力查找。搜索结果适合用来选候选项，安装时仍要回到原项目文档。
- **读取兼容性数据**：仓库提供 `plugins.json` 和 `.agents/plugins/marketplace.json`，供注册表和自动化流程读取。手动找扩展时直接看 README 即可，不需要导入这两个文件。

## 怎么安装和使用 awesome-ai-plugins？

目录本身不需要安装，也没有可用的 DSH 安装命令。README 里的扫描器示例面向扩展开发者，不是把目录装进客户端的步骤。

1. 打开 `hashgraph-online/awesome-ai-plugins` 的 README，找到社区插件下的 DeepSeek Harness 专区，或从 README 进入注册表搜索。
2. 打开目标条目链接的项目仓库，先确认它是否明确支持 DSH，再找对应的安装步骤。如果文档只提供其他客户端的命令，不要直接照搬，也不要用仓库名猜测 npm 包名。
3. 按原项目文档指定的位置填写配置。只有在文档说明需要为某个 `profile` 配置时，才按其指引选择目标；目录没有供所有条目共用的配置文件。
4. 安装后，在你准备使用的 `profile` 下确认扩展已启用，再按原项目给出的用法试一次。若项目文档未说明如何在当前客户端调用，就先核对兼容性，而不是反复重装。

## awesome-ai-plugins 报错怎么排查？

先分清尝试安装的是目录还是目录里的扩展。如果拿目录的仓库名当包名，应停止安装，返回选中的条目核对项目文档。若装的是具体扩展，但安装后无法使用，可以依次做以下检查：

- **核对 `profile`**：确认当前会话使用的配置环境与安装扩展时选择的一致。
- **确认启用状态**：安装和启用不是一回事，检查扩展是否已在当前环境中启用。
- **重启 DSH 后再试**：用同一套配置重启，并按项目文档给出的方式重试，确认问题是否仍然出现。
- **查看版本和日志**：对照原项目写明的兼容要求检查版本，再查看启动或调用时的日志，区分问题发生在安装、加载还是使用阶段。
