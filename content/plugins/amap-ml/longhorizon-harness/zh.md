## LongHorizon-Harness 是做什么的？

LongHorizon-Harness 是一个面向长任务执行与恢复的 DSH 插件市场集成项目。它以独立工具运行，把 DeepSeek Harness 接入多轮执行流程，而不是作为常规 DeepSeek Harness 插件加载，也不替换已有模型。它适合需要分步处理并核验结果的工作，例如整理一批文件、生成汇总报告，再检查报告是否符合要求。

项目整体支持桌面应用和命令行工作流，但 DSH 后端目前只提供命令行接入。网页工作台是用来发起任务、查看进度和处理审批的控制界面，不代表这个后端能操作桌面应用。

## LongHorizon-Harness 核心功能

- **分轮规划**：规划角色根据原始目标、已验证进度和失败证据，决定下一轮要做什么。每轮只处理一个范围明确的步骤，避免把单次操作当成整个任务已经完成。
- **刷新执行上下文**：执行角色用新的上下文处理当前步骤。跨轮需要保留的信息来自任务状态，不依赖把此前的全部对话一直带下去。
- **独立审计**：核验角色查看实际文件、日志或测试结果，不直接采信执行角色的完成声明。未通过核验的结果会留下证据，但不会算作已完成进度。
- **检查点恢复**：通过核验的进度会保存为检查点。任务中断或某一步失败后，后续轮次可以结合上次确认的状态继续，先处理仍未完成的部分。
- **按角色配置后端**：网页工作台支持分别为规划、执行和核验选择后端与模型。DSH 接入使用隔离的 `DSH_HOME`，并按角色划分读写权限。

## 怎么安装和使用 LongHorizon-Harness？

现有 README 摘录没有给出 DSH 安装命令，仓库资料也未确认 npm 包名。请在完整 README 的用法章节查找独立工具的安装步骤，不要把仓库名直接当作 npm 包名。项目标注的 Python 要求是 3.10 或更高版本。

1. 装好工具后，运行 `lh-harness web` 打开网页工作台，在任务设置中按角色选择 DeepSeek Harness 和对应模型。
2. 如果从命令行运行，在任务命令中用 `--agent deepseek_harness` 选择后端；工具会通过 `dsh --profile headless` 调用它。任务默认在启动命令时所在的目录中执行，提交前先确认目录是否正确。
3. 填写任务时同时写明交付物和验收条件，例如报告需要包含哪些字段。运行后在工作台查看各轮结果，按需处理审批；如果要补充要求，可以在运行中发送说明。

## LongHorizon-Harness 报错怎么排查？

- **后端无法启动**：先确认 `dsh` 能在当前环境中调用，再检查选用的后端和 `headless` 配置档。项目提供 `doctor` 诊断；结合版本和运行日志，区分问题发生在启动阶段还是任务执行阶段。
- **恢复旧任务后审批异常，或命令行输出出现编码问题**：查看当前版本。README 记载 v0.1.8 修复了历史运行恢复后的审批问题，以及非 UTF-8 的命令行和 DeepSeek 输出问题；升级前可先查看该版本说明。
- **长时间等不到最终答复**：如果日志显示运行已进入收尾阶段，v0.1.8 提供 `--final-response-timeout`，可为较慢的最终回复留出更多时间。若仍卡在某一轮，先看该轮的执行记录和核验结果。
